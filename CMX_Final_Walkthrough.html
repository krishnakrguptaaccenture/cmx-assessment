01 • The problem

One journey, three perspectives

◎

Claimant

Report an incident, track progress, respond to requests, and receive a decision.

  • Visibility without phone or email follow-up
  • Ownership-protected access
  • Clear state progression
⌁

Claims staff

Pick up incoming work, request evidence, assess risk, and recommend an outcome.

  • Market-scoped work queue
  • Atomic claim assignment
  • Structured assessment workflow
◇

Manager

Review submitted assessments and make the final approve or reject decision.

  • Pending review queue
  • Market-aware authorisation
  • Recorded decision trail

06 • Security

Identity, ownership, assignment, and market boundaries

Request guardrail

JWTuserId, roles, markets, team
→
Controllerrole-level method security
→
Servicebusiness authorisation
→
Repositoryowner / market scoped query
✓Claimant ID comes from the authenticated principal, never the payload.
✓Staff can only access claims in assigned JWT markets.
✓Assessment and information requests require active claim assignment.
✓Revoked tokens are checked by the authentication filter.
✓Passwords, tokens, sensitive free text, and decision reasons stay out of logs.
07 • Events

Post-commit reactions without premature infrastructure

IncidentReportedClaim created exactly once
→
InformationRequestedIn-app notification logged
→
AssessmentSubmittedClaim ready for decision
→
DecisionMadeFinal notification logged

Why Spring events?

One deployable application, lower operational coupling, fast local demonstration.

Reliability boundary

Listeners run after commit. Notification persistence starts a new transaction.

Future seam

The event contracts can later be translated into Kafka envelopes without changing core use cases.

08 • Demo narrative

A smooth walkthrough in seven moves

Authenticate

Login as claimant, staff, and manager. Highlight role and market claims.

Report

Create an incident with an item and party. Show the generated incident and claim.

Assign

Open the staff queue and atomically assign the reported claim.

Request evidence

Create an information request, then submit the claimant response.

Assess

Save a draft, validate it, and submit a recommendation.

Decide

Approve or reject as manager and show the final state and history.

Observe
